# Codec 2 3200: format and decoder (clean-room spec)

**Status:** revision 1 (P1a), 2026-11-24. Format and decoder half only; the encoder half is P1b.
**Written by:** the spec writer, from `codec2.pdf` (read as a document, nothing copied), black-box runs of upstream's
`c2enc`, `c2dec` and `c2sim`, and the codebook data files read as lists of numbers. No upstream source was opened.
**Read this first:** [How complete this is](#how-complete-this-is). The frame format and the quantizers are settled.
The envelope, interpolation and levels are settled to within about 1 dB. The phase model, the voicing rule, the
exact post filter and the synthesis window are **not** settled and are listed as open questions
([Open questions](#open-questions)); an implementer builds those parts from the description here and tunes them
against `c2dec` output, or waits for a logged source read.

## 1. Terms

| Term here | Codec 2 docs | RadioFoundry | Meaning |
|---|---|---|---|
| codec frame | frame | (audio) block | 20 ms, 160 samples, 64 bits at 3200 |
| sub-frame | 10 ms frame | — | Codec 2 analyses and synthesizes every 10 ms (80 samples); a 3200 codec frame describes two. Here: sub-frame **a** (first) and **b** (second) |
| stream frame | — | — | M17's 40 ms frame: two codec frames. M17 code only, never in the library |
| `w0` | Wo | `mbe_params_t.w0` | Fundamental. Stored as in `core/mbe/mbe.h`: phase step per sample, 2^32 = one turn |
| LSP | LSP | — | Line spectral pairs (also called LSFs); the LPC envelope's coded form |
| energy | E | — | Frame energy, quantized in dB |
| voicing | voicing | `v[]` | One bit per sub-frame at 3200 |

Also: `L` is the number of harmonics, `L = floor(pi / w0)` `[pdf §3.2]`; `m` is the harmonic number 1..L; `Fs` = 8000 Hz;
frequencies in Hz unless a symbol says radians per sample.

## 2. The 64-bit frame

### 2.1 Layout

One codec frame is **8 bytes = 64 bits**. Bit 0 is the first transmitted bit and is the **most significant bit of
byte 0**; bit 63 is the least significant bit of byte 7. Fields are packed in this order with no padding
`[exp: tools/blackbox/x01_header_and_layout.py]`, `[exp: tools/blackbox/x02_pitch_field.py]`,
`[exp: tools/blackbox/x03_energy_field.py]`, `[exp: tools/blackbox/x04_lsp_fields.py]`:

| Bits | Width | Field | Coding |
|---|---|---|---|
| 0 | 1 | voicing, first sub-frame (a) | 1 = voiced. See OQ-1 |
| 1 | 1 | voicing, second sub-frame (b) | 1 = voiced. See OQ-1 |
| 2-8 | 7 | `w0` index `i`, 0..127 | Gray coded, MSB first |
| 9-13 | 5 | energy index `e`, 0..31 | Gray coded, MSB first |
| 14-18 | 5 | LSP delta index `d1` (table `dlsp1`) | Gray coded |
| 19-23 | 5 | `d2` (`dlsp2`) | Gray coded |
| 24-28 | 5 | `d3` (`dlsp3`) | Gray coded |
| 29-33 | 5 | `d4` (`dlsp4`) | Gray coded |
| 34-38 | 5 | `d5` (`dlsp5`) | Gray coded |
| 39-43 | 5 | `d6` (`dlsp6`) | Gray coded |
| 44-48 | 5 | `d7` (`dlsp7`) | Gray coded |
| 49-53 | 5 | `d8` (`dlsp8`) | Gray coded |
| 54-58 | 5 | `d9` (`dlsp9`) | Gray coded |
| 59-63 | 5 | `d10` (`dlsp10`) | Gray coded |

Total 2 + 7 + 5 + 50 = 64. This matches the allocation in the PDF `[pdf §2.5, table 1]` (pitch 7, spectral
amplitudes 50, energy 5, voicing 2). The order and the Gray coding are not in the PDF; they are from experiment.

**How the layout was found.** Flipping each of the 64 bits of a voiced frame and decoding showed: bits 0-8 change the
pitch of the output (bits 0-1 turn the voicing off, giving noise), bits 9-13 change only the level, bits 14-63
change only the spectral shape (x01). Encoding tones and pulse trains of known pitch showed that the first nine bits
carry a nearly monotone number only after Gray decoding bits 2-8, and the bits above bit 8 do not depend on pitch
(x02). A frame is unambiguous: a worked example is `d6 75 ef 7b de f7 bd ef` hex, voicing 1,1, `i` = 55, `e` = 22 and
all ten LSP indices 10; it decodes to f0 = 200.39 Hz.

### 2.2 Gray code

Every multi-bit field is the **binary-reflected Gray code** of its index `[exp: x02, x03, x04]`:
`gray = n XOR (n >> 1)`; the inverse is `n = gray XOR (gray >> 1) XOR (gray >> 2) XOR ...` until the shifted term is 0.
Indices are decoded with the inverse before use; the tables below are indexed by the decoded index. Evidence: with
the raw field values as the sweep variable the decoded pitch, level and spectral centroid are not monotone, with the
Gray-decoded value they are (x02 table, x03 table, x04 part A).

### 2.3 File header (not part of the frame)

`c2enc` writes a 7-byte header **only when the output file name ends in `.c2`**: `c0 de c2 01 02 <mode> 00`, with
the mode byte 0x00 for 3200 (0x01 for 2400, 0x02 for 1600, 0x08 for 700C). `c2dec` accepts a file with or without it
`[exp: tools/blackbox/x01_header_and_layout.py]`. M17 carries bare 8-byte frames, and the library takes bare frames.
The frames are identical with and without the header. (This resolves the 7-byte offset seen on first use.)

## 3. Quantizers and dequantizers

### 3.1 Voicing

Two bits, one per sub-frame, 1 = voiced. What the decoder does with the two bits is **not** simply "voiced if the
bit is set": see OQ-1 for the observations. `[exp: tools/blackbox/x08_voicing_and_state.py]`

### 3.2 `w0` (7 bits)

Dequantize with `f0 = 50 + 350 * i / 128` Hz, `i` the decoded index 0..127 `[exp: x02]`. In radians per sample:

```
w0 = 2*pi * f0 / 8000 = Wmin + i * (Wmax - Wmin) / 128,   Wmin = 2*pi/160,  Wmax = 2*pi/20
```

So index 0 is 50.000 Hz (period 160 samples), index 127 is 397.27 Hz, and 400 Hz would be index 128 and is never
produced. Measured f0 matched this to 0.001 Hz at 14 indices (largest error 0.5 Hz, at the two highest indices,
where a harmonic sits at the band edge) and the harmonics of the decoded signal sit exactly at `m * f0`. The
alternative divisor 127 (so that index 127 = 400 Hz) was measured and rejected: at index 127 the decoder gave
396.8 to 397.3 Hz, not 400. For the library's phase step: `w0_u32 = round(2^32 * f0 / 8000)`.

The range matches the stated pitch estimation range, 50-400 Hz `[pdf §3.4]`. The first harmonic is dropped at low
pitch, see 6.4. Every one of the 128 indices decodes to a periodic voiced signal (x08 part E).

### 3.3 Energy (5 bits)

Decoded index `e` = 0..31. The output level rises by **1.5625 dB per step** `[exp: tools/blackbox/x03_energy_field.py]`
(measured 1.56-1.57 dB per step over e = 3..23, least-squares slope 1.5656; 50/32 = 1.5625; the steps near e = 0 are
noisier because the output is only a few counts). Values near
e = 31 saturate at the 16-bit output range. How `e` sets the absolute level, together with the envelope, is in 6.3.

The encoder-side meaning (what it measures) is for P1b; the PDF calls it the average level of the spectral amplitudes,
the "AF gain" of the frame `[pdf §2.5]`, and the LPC energy `E = G^2` `[pdf §3.7]`.

### 3.4 LSPs (50 bits)

Ten scalar quantizers on **differences**. For `j` = 1..10, the decoded index `d_j` selects a value `D_j[d_j]` in Hz from
table `j`; the dequantized LSP frequencies are the running sum `[exp: tools/blackbox/x04_lsp_fields.py]`:

```
f_1 = D_1[d_1]        f_j = f_(j-1) + D_j[d_j]     (Hz),   w_j = 2*pi * f_j / 8000   (radians)
```

This is "LSP differences are quantised" `[pdf §4]` made exact: the first difference is relative to 0 Hz. Tables
(values in Hz, 32 entries each, index 0 first):

| Table | Values |
|---|---|
| `dlsp1`, `dlsp2`, `dlsp3`, `dlsp7`, `dlsp8`, `dlsp9`, `dlsp10` | 25, 50, 75, ... , 800 (step 25: entry `k` is `25*(k+1)`) |
| `dlsp4`, `dlsp5`, `dlsp6` | 25, 50, 75, 100, 125, 150, 175, 200, then 250, 300, ... , 1400 (step 50: entry `k >= 8` is `200 + 50*(k-7)`) |

(from the codebook files `dlsp1.txt` .. `dlsp10.txt` in upstream's `src/codebook/`, each a header line `1 32`
then 32 numbers; these are the only codebook files the 3200 decoder uses, see the answer to I-2.) The tables are
generated by the two rules above, so they can be produced by formula, but the implementation's table importer should
still check them value by value against the files (design section 1, "The tables and an MIT release").

Group order: a sweep of each group with the others held (x04 part A) shows group 1 (bits 14-18) moves the whole
spectrum the most and group 10 (bits 59-63) the least, as a chain that starts at 0 Hz must. The decoded spectrum
follows the model built from this running sum with a regression slope of 1.03 (x04 part B).

The unit conversion between table Hz and radians is `w = 2*pi*f/8000` `[exp: x04]` (equivalently f / 4000 * pi).
The library holds LSPs as integers in Hz (the design's "tables' own unit"); every table value is a multiple of 25 Hz,
every sum is too.

**Sums above 4 kHz and other out-of-range cases.** The maximum sum is 9800 Hz. Such frames decode without error and the
output stays bounded (x08 part D), but what the decoder does to the LSPs (clamping, forced ordering or minimum
separation) was not characterised: OQ-8. Frames from `c2enc` never exercise this (its LSP set is derived from a
valid LPC).

## 4. Sub-frames and interpolation

A codec frame decodes to two sub-frames, **a** (first 10 ms) and **b** (second 10 ms). The fields describe **b**.
Sub-frame a is derived by interpolating between the previous frame's b parameters and this frame's `[pdf §2.4, §3.7]`
(the PDF says linear interpolation at the 10 ms rate; the weights are from the experiments below).

**Timing** `[exp: tools/blackbox/x07_interpolation.py]`: a frame `k` covers output samples `160k .. 160k+159`. Its
sub-frame a is centred on sample `160k + 80` and its sub-frame b on `160k + 160` (the first sample of the next frame).
Amplitudes follow straight ramps between those centres: the envelope of a harmonic was a piecewise-linear ramp whose
knots are the sub-frame values at those times. This is what a triangular overlap-add window of length 160 and hop 80
produces `[pdf §3.3]`.

| Parameter | Sub-frame a value | Evidence |
|---|---|---|
| Energy | Midpoint in **dB** of previous-b and current-b (the geometric mean of the amplitudes) | x07 part A: at knot a the amplitude was 243.9 vs geometric mean 240.7 (arithmetic mean 344.9); 293.4 vs 288.0 (642.1); falling and rising steps agree |
| LSPs | Midpoint of the two sets, in Hz (weight 0.5) | x07 part B: best weight 0.5 in 3 of 4 cases (0.6 in the other) with rms error at the best weight of 0.6-1.4 dB against 2-8 dB at weights 0 and 1 |
| `w0` | Midpoint (weight 0.5) when both frames are voiced | `[pdf §2.4]` gives the example "200 Hz then 220 Hz gives 210 Hz for the middle frame". **Not measured**; see OQ-2 for the other cases |
| Voicing | not a plain copy of the bit | OQ-1 |

Sub-frame b uses the current frame's decoded values directly. The decoder keeps the b values (w0, voicing, energy
index in dB, LSPs in Hz) for the next frame.

**Start-up.** Before the first frame the previous-b state is unknown (OQ-7). Observed: a single frame decodes to 160
samples, and with identical frames the output level ramps from near zero to full over the first frame (x08 part C:
block rms 59, 171, 268, 458, then steady 607).

## 5. LSP to LPC

Standard textbook construction `[lit: LSP representation, Itakura 1975 (pdf ref 4); textbook LPC, e.g. Kondoz 1994
(pdf ref 6); not re-read this session, the formula is the usual one]`, with the tenth-order polynomials of
`[pdf §3.7, eq. 33-34]` and confirmed against the decoder `[exp: x04]`:

```
P(z) = (1 + z^-1)  * Product_{i=1,3,5,7,9}  (1 - 2*cos(w_i) * z^-1 + z^-2)
Q(z) = (1 - z^-1)  * Product_{i=2,4,6,8,10} (1 - 2*cos(w_i) * z^-1 + z^-2)
A(z) = (P(z) + Q(z)) / 2          a_0 = 1, coefficients a_1..a_10 of z^-1 .. z^-10
```

(the PDF's printed formula has a misplaced bracket; this is the usual form). `H(z) = G / A(z)`. The decoder's spectrum
follows `1/|A|` computed this way: the regression of measured harmonic level on `-20 log10 |A(f)|` over 40 random
frames had slope 1.03 and residual 1.0 dB once the post-filter terms below are included (x04 part B), so the
frequencies, ordering and bandwidths are right.

## 6. The envelope at the harmonics

For each sub-frame the decoder needs `A_m`, the amplitude of harmonic `m` = 1..L.

### 6.1 The form

`[pdf §3.7, eq. 35-36]`: take the `N_dft`-point DFT of the LPC model `H(k)`, apply the post filter to its power
spectrum, then set `A_m^2` to the **sum** of the (post-filtered) power over the DFT bins of harmonic `m`'s band. With
`r = w0 * N_dft / (2*pi)` (bins per harmonic spacing), the band is the bins from `a_m = round((m - 0.5) * r)` up to but
not including `b_m = round((m + 0.5) * r)` `[pdf §3.2, eq. 9]`. Measured: the total harmonic power of the output
divided by the sum of band sums of `1/|A|^2` over the harmonic bands, with `N_dft` = 512, is constant (28.4-29.3 dB,
standard deviation 0.8-1.1 dB per frame) from f0 = 64 Hz to 397 Hz (x03 part B), whereas the same quantity taken from
point samples of `1/|A|^2` at the harmonic frequencies drifts by 9 dB over that range. So the amplitude is a band
**sum** (it grows with the number of bins in the band), not a point sample or a band mean.

`N_dft`: the PDF gives 512 only for the pitch estimator's DFT and says only that the synthesis DFT is longer than twice
the 80-sample hop `[pdf §3.3]`. The experiments cannot tell 256 from 2048 (any `N_dft` gives a constant offset, and
the shape error is 2.76 dB at 256, 2.68-2.70 dB from 512 up, 2.97 dB at 128: x05 part C). The recommended and design-assumed value is **512** (which
also lets the RadioFoundry seam serve it, see I-6). OQ-6.

### 6.2 Post filter and bass boost

`c2dec --nopf` has **no effect** at 3200: the output is identical bit for bit with and without it
`[exp: tools/blackbox/x05_post_filter.py]`. The post filter and the low-frequency boost are always applied.

Description `[pdf §3.7, eq. 37]`: `P_f(w) = g * R_w(w)^beta`, `R_w = A(z/gamma) / A(z)` (bandwidth-expanded numerator,
coefficients `a_k * gamma^k`), `beta = 0.2`, `gamma = 0.5`, `g` chosen to normalise the gain; "a step change at 1000 Hz
is a +3 dB low-frequency boost".

Measured, as a regression of harmonic level (dB, 300-3400 Hz) on `-20 log10|A|`, `20 log10 |A(z/0.5)/A(z)|` and a
below-1-kHz indicator (x04 part B, 40 frames): coefficients **1.031, 0.169, 2.79 dB**. The first two give an
effective `|1/A|^1.20 * |A(z/0.5)|^0.17` shaping in amplitude, consistent with `beta` about 0.2, `gamma` 0.5, and a
bass step of about **+2.8 to +2.9 dB below 1000 Hz** (3 dB in the PDF). The grid search over (gamma, beta, step before
or after normalisation, band sum or point) in x05 does not pin gamma and beta apart: the best five variants span
gamma 0.4-0.6 and beta 0.25-0.3 within 0.15 dB of each other (score 3.49-3.61 dB; no post filter at all scores 3.88),
all with the step applied after a sum-preserving normalisation, band-sum sampling preferred. The post filter is
therefore real but its effect is small compared with the measurement scatter. **The exact constants and the normalisation are therefore OQ-3.** An
implementation using `gamma = 0.5`, `beta = 0.2` and a +3 dB step for harmonics below 1000 Hz (bin < 64 of 512)
reproduces the measured envelope to about 1 dB rms over 300-3400 Hz; deeper LPC valleys and the band edges (below
300 Hz, above 3400 Hz) deviate by up to 9 dB in the experiments and are not explained (OQ-3).

### 6.3 Level

Let `a_m` be the peak amplitude of harmonic `m` in the output (16-bit units) and `B_m` the band sum of
`1/|A(e^{j2*pi*k/512})|^2` over the bins of harmonic `m` (6.1; `A` is the monic LPC polynomial of section 5, `a_0` = 1,
before any post filter). Then, summed over the harmonics that are present (6.4)
`[exp: tools/blackbox/x03_energy_field.py]`:

```
10*log10( sum_m a_m^2 )  =  10*log10( sum_m B_m )  +  28.8 dB  +  1.5625 dB * (e - 20)         (+-1 dB per frame)
```

Mean-square of the output signal is `sum a_m^2 / 2`. The constant 28.8 dB is the mean of the per-w0 offsets in x03
part B (28.2-29.3 dB); the plus or minus 1 dB is the frame-to-frame standard deviation, not measurement noise alone, so
the true rule probably normalises something this does not (OQ-4). Level accuracy within ±1 dB is what design check D2
needs, so this suffices to start; P3 calibrates against `c2dec`.

The PDF's `E = G^2` reading (the LPC gain squared) is not contradicted: `e` sets an overall scale and the shape comes
from `1/|A|` with `a_0 = 1`; the band-sum law above is that statement with the DFT's scaling folded into the constant.

### 6.4 Which harmonics exist

- `L = floor(pi / w0)` `[pdf §3.2]`. Harmonics are exactly at `m * f0` (x02).
- **Harmonic 1 is absent when f0 is below about 150 Hz**: for decoded `i` <= 36 (f0 <= 148.4 Hz) harmonic 1 was 28 to
  64 dB down; for `i` >= 37 (f0 >= 151.2 Hz) it was present; harmonics 2, 3 and up were unaffected at every pitch,
  including 50 Hz `[exp: tools/blackbox/x06_first_harmonic.py]`. Held for three envelopes and two energies. The
  threshold lies in (148.4, 151.2] Hz; it was not located on interpolated (non-grid) pitches (OQ-2). Treat it as: skip
  `m = 1` when `w0 < 2*pi*150/8000`.
- Harmonics near the band edges (below 300 Hz, above 3400 Hz) deviated from the model in some frames by up to 9 dB
  for reasons the experiments did not explain (see 6.2, OQ-3).

## 7. Phase model (voiced and unvoiced)

State: **open**; described from the PDF `[pdf §3.6]`, which says only what follows. Behaviours that were measured
are marked.

1. Each harmonic's phase is the sum of an **excitation phase** `phi_m` and the phase of the synthesis filter at that
   harmonic: `theta_m = phi_m + arg H(e^{j m w0})`.
2. **Voiced**: the excitation is a pulse train. The first harmonic's excitation phase advances by `N * w0` per
   sub-frame (`N` = 80 samples): `phi_1[l] = phi_1[l-1] + N*w0`, and `phi_m = m * phi_1` for `m` = 2..L. Measured
   consistent with this: in a steady voiced decode the harmonics sit exactly at `m * f0` (x02), which is what a phase
   that advances by `m * w0 * N` per sub-frame gives.
3. **Unvoiced**: the excitation phase of each harmonic is drawn uniformly from (-pi, pi) every sub-frame, and the PDF
   says to use `F0 = 50 Hz` (`L` = 80) so as to approximate noise. The decoder is **deterministic** (the same input
   always gives the same samples, x08 part B), so its noise generator has a fixed seed. For an unvoiced sub-frame
   the output was **not** independent of the transmitted `w0` (x08 part B: w0 index 5 and 100 gave different
   samples), so how `w0` and `L` are used for unvoiced frames is OQ-1/OQ-5.
4. The filter phase `arg H` is the **minimum-phase** response matching the magnitude response of `1/A` sampled at the
   harmonic centres, bin `round(m * r)` `[pdf §3.6, eq. 36]`; the standard way is the cepstrum (or the Hilbert relation
   between log magnitude and phase) `[lit: standard DSP textbook material, not consulted this session]`. Which
   construction and which sizes: OQ-5.
5. A noise-floor rule: the decoder measures the average background level in unvoiced frames, and any harmonic below
   it gets random phase, i.e. is treated as unvoiced `[pdf §3.6]`. Constants: OQ-5.
6. No attempt is made to keep the final phase (after the filter) continuous across sub-frames; only the excitation
   phase is continuous `[pdf §3.6, note 5]`.

Because randomness only perturbs phases, **bit-exact random numbers are not needed** for design check D2 (log-spectral
distance); any uniform generator seeded per decoder instance is acceptable, so long as it is deterministic
`[c2fx design]`.

## 8. Synthesis

`[pdf §3.3]`, with the timing confirmed by the amplitude ramps measured in x07:

1. For each sub-frame fill a spectrum array of `N_dft` bins with zeros; for each harmonic `m` = 1..L put the complex
   value `A_m * exp(j*theta_m)` at bin `round(m * r)` (`r` as in 6.1), and its conjugate at the mirrored bin so the
   result is real `[pdf eq. 10-11]`.
2. Inverse DFT (`N_dft` points, real output). `N_dft` > 2N = 160 `[pdf §3.3]`.
3. Window the 160-point result with a **triangular** window `t(n) = n/80` for `n` = 0..79 and `2 - n/80` for `n` =
   80..159 `[pdf eq. 13]`; adjacent windows 80 samples apart sum to 1 `[pdf eq. 14]`. (The PDF says the window shape is
   not important so long as it sums to 1; whether upstream uses exactly this shape and how it picks the 160 samples
   out of the `N_dft`-point IDFT are OQ-6; the timing of the amplitude ramps, centres at 160k+80 and 160k+160, was
   confirmed in x07.)
4. Overlap-add: output samples `0..79` of the sub-frame are the first half of the windowed block plus the stored second
   half of the previous sub-frame's block; the second half (samples 80..159) is stored for the next sub-frame
   `[pdf §3.3, eq. 15]`.
5. Rounding to int16 with saturation at +-32767 (observed clipping, x08).

**I-6: are all FFTs 512 points?** The PDF names one DFT size: 512, for the pitch estimator (encoder side). For the
decoder it gives only a bound (more than 160). The experiments cannot tell sizes from 256 up apart (they all give a
constant level offset and the same shape error, so the envelope DFT being 512 is neither confirmed nor refuted). The
design's assumption holds up to this: if the decoder's `N_dft` is 512 then `mbe_rfft`/`mbe_irfft` serve every FFT the
decoder needs (envelope: a 512-point power spectrum of a 11-tap filter response; synthesis: a 512-point inverse). OQ-6
asks for the one constant that settles it.

## 9. Lost frames `[c2fx design]`

Upstream's decoder has no lost-frame handling (it always decodes the frame it is given). This section is **our own
design**, as `40-design.md` (API section) says: `c2fx_decode(d, NULL, pcm, scratch)` means "frame lost".

- Repeat the previous frame's model (w0, LSPs, voicing as decoded for sub-frame b) for the lost frame, with the
  energy index lowered by a fixed number of steps per consecutive lost frame (starting proposal: 2 steps = 3.125 dB),
  for a fixed maximum run (starting proposal: 4 frames = 80 ms). After the run, output silence and keep the state so a
  good frame next fades in through the normal start-up path.
- Sub-frame a of the lost frame is the interpolation of the previous b with the repeated (decayed) b, as for any frame.
- The run length and the decay are parameters P3 fixes with the float model and holds to the D4 check ("mutes after the
  repeat limit"). The constants above are starting points, not facts about upstream.

Deciding that a frame is bad stays with the caller (the M17 layer).

## 10. Encoder (P1b)

Reserved. P1b adds the analysis, pitch, voicing, LPC and LSP computation, energy measurement and the quantizers'
forward direction here and in `docs/spec/c2-3200-encoder.md`, or as a section of this file. The inverse of the
quantizers above is not given here beyond what the experiments showed of `c2enc`'s output: its w0 indices follow

## Answers to the questions this phase had to settle

**I-1. How much of 3200 does `codec2.pdf` give?** It gives: the bit allocation (7 pitch, 5 energy, 2 voicing,
50 for the spectral amplitudes; table 1 and table 2), that LSP **differences** are quantised and that this costs
robustness to bit errors, that frames are 20 ms with a 10 ms internal rate and linear interpolation of the parameters
between, the pitch search range (50-400 Hz) and `L = floor(pi/w0)`, the structure of the post filter with
`beta = 0.2`, `gamma = 0.5` and a +3 dB step at 1000 Hz, the zero-order phase model, the IDFT overlap-add synthesis
and the triangular window with hop 80. It does **not** give: the field order, the Gray coding, the `w0` and energy
ranges and steps, the tables, the interpolation weights, the voicing rule, or any constant of the phase model and the
level normalisation. Those are filled in from experiment here.

**I-2. Which codebook files hold the 3200 tables, how many values?** `dlsp1.txt` through `dlsp10.txt` (upstream's
`src/codebook/`; one file per LSP difference), each a header line `1 32` and 32 values in Hz: **10 files, 320 numbers**.
The other LSP files (`lsp1..10.txt`, `lsp8910.txt`, `lspjmv*`, `lspvqexp*`) belong to other modes; `gecb.txt`,
`newamp*`, `codes_450.txt`, `train_*` are not 3200. `w0` and the energy have **no table**: they are formulas
(3.2, 3.3). All ten files follow two regular patterns (3.4), so the importer can check them against a formula.

**I-3 (bonus).** `c2sim ... --modelout <file>` writes a model dump with no source change (record layout in
`tools/blackbox/README.md`); with `--rate 3200` the dumped `w0` is already on the 3200 grid. Useful for P2's
`_params.csv`; the record's fields were inferred from size and values only.

**I-6.** See section 8: the PDF names 512 only for the encoder's pitch DFT; the decoder's synthesis size is not stated
and not decidable by the experiments; the design's assumption (512) is consistent with everything seen, and OQ-6 holds
the one constant that settles it.
