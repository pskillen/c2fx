## 1. Terms

| stream frame | — | — | M17's 40 ms frame: two codec frames. M17 code only, never in the library |
| `w0` | Wo | `mbe_params_t.w0` | Fundamental. Stored as in `core/mbe/mbe.h`: phase step per sample, 2^32 = one turn |

Also: `L` is the number of harmonics, `L = floor(pi / w0)` `[pdf §3.2]`; `m` is the harmonic number 1..L; `Fs` = 8000 Hz;
frequencies in Hz unless a symbol says radians per sample.

## 2. The 64-bit frame

### 2.1 Layout

One codec frame is **8 bytes = 64 bits**. Bit 0 is the first transmitted bit and is the **most significant bit of
byte 0**; bit 63 is the least significant bit of byte 7. Fields are packed in this order with no padding
`[exp: tools/blackbox/x01_header_and_layout.py]`, `[exp: tools/blackbox/x02_pitch_field.py]`,
`[exp: tools/blackbox/x03_energy_field.py]`, `[exp: tools/blackbox/x04_lsp_fields.py]`:

| Bits | Width | Field | Coding |
|---|---|---|---|
| 0 | 1 | voicing of sub-frame a (the first, interpolated one) `[src: codec2.c @ 310777b]` | 1 = voiced. See 3.1 and OQ-1 |
| 1 | 1 | voicing of sub-frame b (the second one, carrying `w0`, energy and LSPs) `[src: codec2.c @ 310777b]` | 1 = voiced. See 3.1 and OQ-1 |
| 2-8 | 7 | `w0` index `i`, 0..127 | Gray coded, MSB first |
| 9-13 | 5 | energy index `e`, 0..31 | Gray coded, MSB first |
| 14-18 | 5 | LSP delta index `d1` (table `dlsp1`) | Gray coded |
| 19-23 | 5 | `d2` (`dlsp2`) | Gray coded |
| 24-28 | 5 | `d3` (`dlsp3`) | Gray coded |
| 29-33 | 5 | `d4` (`dlsp4`) | Gray coded |
| 34-38 | 5 | `d5` (`dlsp5`) | Gray coded |
| 39-43 | 5 | `d6` (`dlsp6`) | Gray coded |
| 44-48 | 5 | `d7` (`dlsp7`) | Gray coded |
| 49-53 | 5 | `d8` (`dlsp8`) | Gray coded |
| 54-58 | 5 | `d9` (`dlsp9`) | Gray coded |
| 59-63 | 5 | `d10` (`dlsp10`) | Gray coded |

Total 2 + 7 + 5 + 50 = 64. This matches the allocation in the PDF `[pdf §2.5, table 1]` (pitch 7, spectral
amplitudes 50, energy 5, voicing 2). The order and the Gray coding are not in the PDF; they are from experiment.

**How the layout was found.** Flipping each of the 64 bits of a voiced frame and decoding showed: bits 0-8 change the
pitch of the output (bits 0-1 turn the voicing off, giving noise), bits 9-13 change only the level, bits 14-63
change only the spectral shape (x01). Encoding tones and pulse trains of known pitch showed that the first nine bits
carry a nearly monotone number only after Gray decoding bits 2-8, and the bits above bit 8 do not depend on pitch
(x02). A frame is unambiguous: a worked example is `d6 75 ef 7b de f7 bd ef` hex, voicing 1,1, `i` = 55, `e` = 22 and
all ten LSP indices 10; it decodes to f0 = 200.39 Hz.

### 2.2 Gray code

Every multi-bit field is the **binary-reflected Gray code** of its index `[exp: x02, x03, x04]`:
`gray = n XOR (n >> 1)`; the inverse is `n = gray XOR (gray >> 1) XOR (gray >> 2) XOR ...` until the shifted term is 0.
Indices are decoded with the inverse before use; the tables below are indexed by the decoded index. Evidence: with
the raw field values as the sweep variable the decoded pitch, level and spectral centroid are not monotone, with the
Gray-decoded value they are (x02 table, x03 table, x04 part A).

### 2.3 File header (not part of the frame)

`c2enc` writes a 7-byte header **only when the output file name ends in `.c2`**: `c0 de c2 01 02 <mode> 00`, with
the mode byte 0x00 for 3200 (0x01 for 2400, 0x02 for 1600, 0x08 for 700C). `c2dec` accepts a file with or without it
`[exp: tools/blackbox/x01_header_and_layout.py]`. M17 carries bare 8-byte frames, and the library takes bare frames.
The frames are identical with and without the header. (This resolves the 7-byte offset seen on first use.)

## 3. Quantizers and dequantizers

### 3.1 Voicing

Two bits, one per sub-frame, 1 = voiced. The first bit read is the voicing of sub-frame a and the second that of
sub-frame b, and each sub-frame's voiced flag is set directly from its own bit; nothing else in those three files
changes it `[src: codec2.c @ 310777b]`.

What the black-box runs show does not look like that, and the difference is not yet explained
`[exp: tools/blackbox/x08_voicing_and_state.py]`: in steady state only (1,1) decodes periodic, (1,0) decodes bit for bit
identical to (0,0), and (0,1) decodes unvoiced-like. So something after the decoder step that sets the flags (the pitch
interpolation, the phase synthesis and the synthesis itself live in files that were not read) must demote or ignore
sub-frame a's voiced flag when sub-frame b is unvoiced, or when the previous sub-frame was unvoiced. What is known
about the pitch of a voiced sub-frame a in mixed frames is in section 4 (x10). The rest stays OQ-1.

### 3.2 `w0` (7 bits)

Dequantize with `f0 = 50 + 350 * i / 128` Hz, `i` the decoded index 0..127 `[exp: x02]`. In radians per sample:

```
w0 = 2*pi * f0 / 8000 = Wmin + i * (Wmax - Wmin) / 128,   Wmin = 2*pi/160,  Wmax = 2*pi/20
```

So index 0 is 50.000 Hz (period 160 samples), index 127 is 397.27 Hz, and 400 Hz would be index 128 and is never
produced. Measured f0 matched this to 0.001 Hz at 14 indices (largest error 0.5 Hz, at the two highest indices,
where harmonic 10 is faint and the peak search is unreliable; the 12-13 Hz in the x02 deviation column there is that, not a real offset: with a flat envelope harmonic 10 sits exactly at `m * f0`) and the harmonics of the decoded signal sit exactly at `m * f0`. The
alternative divisor 127 (so that index 127 = 400 Hz) was measured and rejected: at index 127 the decoder gave
396.8 to 397.3 Hz, not 400. For the library's phase step: `w0_u32 = round(2^32 * f0 / 8000)`.

The range matches the stated pitch estimation range, 50-400 Hz `[pdf §3.4]`. The first harmonic is scaled down at low
pitch, see 6.4. Every one of the 128 indices decodes to a periodic voiced signal (x08 part E).

### 3.3 Energy (5 bits)

Decoded index `e` = 0..31. The output level rises by **1.5625 dB per step** `[exp: tools/blackbox/x03_energy_field.py]`
(measured 1.56-1.57 dB per step over e = 3..23, least-squares slope 1.5656; 50/32 = 1.5625; the steps near e = 0 are
noisier because the output is only a few counts). Values near
e = 31 saturate at the 16-bit output range. How `e` sets the absolute level, together with the envelope, is in 6.3.

What the encoder measures is for the encoder half. The PDF describes the energy as the mean level of the harmonic
amplitudes, and elsewhere as the LPC energy `E = G^2` `[pdf §2.5, §3.7]`.

### 3.4 LSPs (50 bits)

Ten scalar quantizers on **differences**. For `j` = 1..10, the decoded index `d_j` selects a value `D_j[d_j]` in Hz from
table `j`; the dequantized LSP frequencies are the running sum `[exp: tools/blackbox/x04_lsp_fields.py]`:

```
f_1 = D_1[d_1]        f_j = f_(j-1) + D_j[d_j]     (Hz),   w_j = 2*pi * f_j / 8000   (radians)
```

This is "LSP differences are quantised" `[pdf §4]` made exact: the first difference is relative to 0 Hz. Tables
(values in Hz, 32 entries each, index 0 first):

| Table | Values |
|---|---|
| `dlsp1`, `dlsp2`, `dlsp3`, `dlsp7`, `dlsp8`, `dlsp9`, `dlsp10` | 25, 50, 75, ... , 800 (step 25: entry `k` is `25*(k+1)`) |
| `dlsp4`, `dlsp5`, `dlsp6` | 25, 50, 75, 100, 125, 150, 175, 200, then 250, 300, ... , 1400 (step 50: entry `k >= 8` is `200 + 50*(k-7)`) |

(from the codebook files `dlsp1.txt` .. `dlsp10.txt` in upstream's `src/codebook/`, each a header line `1 32`
then 32 numbers; these are the only codebook files the 3200 decoder uses; see "What the PDF gives" below.) The tables are
generated by the two rules above, so they can be produced by formula, but the implementation's table importer should
still check them value by value against the files.

Group order: a sweep of each group with the others held (x04 part A) shows group 1 (bits 14-18) moves the whole
spectrum the most and group 10 (bits 59-63) the least, as a chain that starts at 0 Hz must. The decoded spectrum
follows the model built from this running sum with a regression slope of 1.03 (x04 part B).

The unit conversion between table Hz and radians is `w = 2*pi*f/8000` `[exp: x04]` (equivalently f / 4000 * pi).
The library can hold LSPs as integers in Hz; every table value is a multiple of 25 Hz,
every sum is too.

**Sums above 4 kHz and other out-of-range cases.** The maximum sum is 9800 Hz. Such frames decode without error and the
output stays bounded (x08 part D), but what the decoder does to the LSPs (clamping, forced ordering or minimum
separation) is answered by the source read: the 3200 decoder builds the LSPs as the running sum above (table Hz to
radians by pi/4000), interpolates them, and passes them straight to the LSP to LPC step with **no clamp, reorder or
minimum separation**; those checks exist only in the decoders of other modes `[src: quantise.c, codec2.c @ 310777b]`.
So a bit-compatible decoder must not add any. c2fx may still add its own guard against unstable filters as a
`[c2fx design]` choice (the effect on frames from `c2enc`, which are always valid, is nil); this spec does not specify
one. Frames from `c2enc` never exercise this (its LSP set is derived from a valid LPC).

## 4. Sub-frames and interpolation

A codec frame decodes to two sub-frames, **a** (first 10 ms) and **b** (second 10 ms). The fields describe **b**.
Sub-frame a is derived by interpolating between the previous frame's b parameters and this frame's `[pdf §2.4, §3.7]`
(the PDF says linear interpolation at the 10 ms rate; the weights are from the experiments below).

**Timing** `[exp: tools/blackbox/x07_interpolation.py]`: a frame `k` covers output samples `160k .. 160k+159`. Its
sub-frame a is centred on sample `160k + 80` and its sub-frame b on `160k + 160` (the first sample of the next frame).
Amplitudes follow straight ramps between those centres: the envelope of a harmonic was a piecewise-linear ramp whose
knots are the sub-frame values at those times. This is what a triangular overlap-add window of length 160 and hop 80
produces `[pdf §3.3]`.

| Parameter | Sub-frame a value | Evidence |
|---|---|---|
| Energy | Midpoint in **dB** of previous-b and current-b (the geometric mean of the amplitudes) | x07 part A: at knot a the amplitude was 243.9 vs geometric mean 240.7 (arithmetic mean 344.9); 293.4 vs 288.0 (642.1); falling and rising steps agree |
| LSPs | Midpoint of the two sets, in Hz (weight 0.5) | x07 part B: best weight 0.5 in 3 of 4 cases (0.6 in the other) with rms error at the best weight of 0.6-1.4 dB against 2-8 dB at weights 0 and 1 |
| `w0` | Midpoint of the two `w0` values (weight 0.5, in Hz or radians alike) when the previous frame's sub-frame b was voiced and sub-frame a is voiced (tested with both bits of the current frame set); the **current frame's** `w0` unchanged when the previous frame's sub-frame b was unvoiced (including the very first frame) | `[pdf §2.4]` describes the average; `[exp: tools/blackbox/x10_w0_interpolation.py]`: a harmonic-comb search at the centre of sub-frame a found 187.0, 215.0, 257.5 Hz against midpoints 186.7, 214.1, 255.1 Hz for voiced-to-voiced steps, and the current pitch (242.0, 269.0, 188.5 Hz) after unvoiced frames. The routine itself is in a file that was not read (it is called with the previous model, the new one and the lowest `w0`) `[src: codec2.c @ 310777b]`. One case (unvoiced then voiced at a lower pitch) gave a comb result at a multiple of the pitch and is not counted |
| Voicing | Set from its own bit `[src: codec2.c @ 310777b]`; the black-box behaviour in mixed frames differs | section 3.1, OQ-1 |

Sub-frame b uses the current frame's decoded values directly. The decoder keeps the b values (w0, voicing, energy
index in dB, LSPs in Hz) for the next frame.

**Start-up.** The decoder's initial previous-b state is `[src: codec2.c @ 310777b]`: previous voiced flag 0; previous
harmonic amplitudes 1..160 all 0; previous LSP `i` (i = 0..9) equal to `i * pi / 11` radians (so LSP 0 is 0); previous
energy 1 (the source read gives the value only; its unit is not stated); previous `w0` = `2*pi` divided by the longest
pitch period the decoder accepts, and previous `L` = `pi` over that `w0`, truncated. The value of that longest period
is not in the files read, so the initial `w0` and `L` are unknown. They cannot be observed from output either: with the
previous flag 0, a voiced first frame takes the current `w0` in sub-frame a (x10 part B), so the initial `w0` never
reaches the output.

Observed: a single frame decodes to 160 samples, and with identical frames the output level ramps from near zero to
full over the first frame (x08 part C: block rms 59, 171, 268, 458, then steady 607).

`[c2fx design]` defaults, since the unit of the initial energy is unknown and the initial phase is not known: the
previous energy starts at the lowest level the energy quantizer can express (index 0), the other previous values are as
listed, the initial phases are zero, and the previous `w0` is any value (it never reaches the output).

## 5. LSP to LPC

The usual construction, with the tenth-order polynomials of `[pdf §3.7, eq. 33-34]`, confirmed against the decoder
`[exp: tools/blackbox/x04_lsp_fields.py]`:

```
P(z) = (1 + z^-1)  * Product_{i=1,3,5,7,9}  (1 - 2*cos(w_i) * z^-1 + z^-2)
Q(z) = (1 - z^-1)  * Product_{i=2,4,6,8,10} (1 - 2*cos(w_i) * z^-1 + z^-2)
A(z) = (P(z) + Q(z)) / 2          a_0 = 1, coefficients a_1..a_10 of z^-1 .. z^-10
```

(the PDF's printed formula has a misplaced bracket; this is the usual form). `H(z) = G / A(z)`. The decoder's spectrum
follows `1/|A|` computed this way: the regression of measured harmonic level on `-20 log10 |A(f)|` over 40 random
frames had slope 1.03 and residual 1.0 dB once the post-filter terms below are included (x04 part B), so the
frequencies, ordering and bandwidths are right.

## 6. The envelope at the harmonics

For each sub-frame the decoder needs `A_m`, the amplitude of harmonic `m` = 1..L.

### 6.1 The form

`[pdf §3.7, eq. 35-36]`: take the DFT of the LPC model `H(k)`, apply the post filter to its power spectrum, then set
`A_m^2` to the **sum** of the (post-filtered, energy-scaled) power over the DFT bins of harmonic `m`'s band.

The DFT is a real FFT of the 11 LPC coefficients of size `FFT_ENC` = **512**, of which the 256 power bins 0..255 are
used, 2*pi/512 radians per bin `[src: defines.h, quantise.c @ 310777b]`. With `r = 2*pi/512` rad per bin, the band of
harmonic `m` is `lo <= k < hi` with `lo = trunc((m - 0.5) * w0 / r + 0.5)` and
`hi = min(trunc((m + 0.5) * w0 / r + 0.5), 256)`, so the upper bin is excluded and bins above 255 never enter
`[src: quantise.c @ 310777b]` for the edges and the cap. The source read gives the cap as "256" without saying whether
the upper edge is included; the half-open reading is the one the experiment supports: with it the fit of x09 reaches 0.74 dB rms at the
best pair, with the upper bin included it is 1.07 dB (gamma 0.6, beta 0.275; 0.99 against 1.04 dB for the PDF pair). This is
the PDF's band `a_m .. b_m` with truncation in place of rounding and a cap. Measured: the total harmonic power of the
output divided by the sum of band sums of `1/|A|^2` over the harmonic bands, with `N_dft` = 512, is constant (28.2-29.3 dB,
standard deviation 0.8-1.1 dB per frame) from f0 = 64 Hz to 397 Hz (x03 part B), whereas the same quantity taken from
point samples of `1/|A|^2` at the harmonic bins drifts from 34.5 to 43.7 dB over that range (x03 prints both columns). So the amplitude is a band
**sum** (it grows with the number of bins in the band), not a point sample or a band mean.

`N_dft`: the PDF gives 512 only for the pitch estimator's DFT. The source read gives `FFT_ENC` = 512 for this envelope
DFT and `FFT_DEC` = 512 for the synthesis inverse FFT `[src: defines.h, codec2.c @ 310777b]`, so **both are 512**. The
experiments could not tell 256 from 2048 (x05 part C), which is why they never settled it.

### 6.2 Post filter and bass boost

`c2dec --nopf` has **no effect** at 3200: the output is identical bit for bit with and without it
`[exp: tools/blackbox/x05_post_filter.py]`. The post filter and the low-frequency boost are on at creation and the 3200
decoder passes both through unchanged, so they are always applied `[src: codec2.c @ 310777b]`.

**Chain** `[src: quantise.c @ 310777b]`, per sub-frame, on the 256 power bins `P(k)` of `1/|A|^2`:

1. Post filter: `P'(k) = P(k) * |A(z/gamma) / A(z)|^(2*beta)` at the bin frequency (`z` on the unit circle), as in the
   PDF's formula below. The source passes `beta` and `gamma` as arguments with defaults from two constants whose values
   are in a file that was not read.
2. Rescale so the sum of `P'` over the 256 bins equals the sum of `P` (each sum having `1E-4` added before the ratio).
3. Multiply by the decoded energy as a linear power, `10^(dB/10)` (6.3).
4. Bass boost: multiply the power in bins 0 to 63 (about 0 to 1 kHz) by 1.4 * 1.4 = **1.96** (+2.92 dB; the source's own
   comment says 3 dB). This is after the rescale and the energy scaling, and exists only inside the post filter.
5. Each harmonic amplitude is the square root of the sum of the bins of its band (6.1); then 6.4's first-harmonic factor.

Description `[pdf §3.7, eq. 37]`: `P_f(w) = g * R_w(w)^beta`, `R_w = A(z/gamma) / A(z)` (bandwidth-expanded numerator,
coefficients `a_k * gamma^k`), with `beta = 0.2`, `gamma = 0.5` given in the PDF, `g` chosen so the filter keeps the overall
gain; the PDF also describes a +3 dB boost of the low frequencies, switching at 1000 Hz.

**Regression** `[exp: tools/blackbox/x04_lsp_fields.py part B]`: harmonic level (dB, 300-3400 Hz) on `-20 log10|A|`,
`20 log10 |A(z/0.5)/A(z)|` and a below-1-kHz indicator, 40 frames: coefficients **1.031, 0.169, 2.79 dB**, i.e. an
effective `|1/A|^1.20 * |A(z/0.5)|^0.17` shaping in amplitude and a bass step of about +2.8 to +2.9 dB (the source's
+2.92 dB). The older grid of x05 (without the chain above) is superseded by x09 and is not used.

**Fit with the full chain** `[exp: tools/blackbox/x09_post_filter_fit.py]`: 48 random frames, 1266 harmonics, everything
fixed as in the chain except `gamma`, `beta` and one global level constant; harmonics predicted more than 40 dB below the
strongest in their frame are left out. The reason: those decode with random phase (the PDF's background-noise rule,
section 7), so a steady-tone measurement of them has a residual of 3-9 dB, against 0.25-0.7 dB for the rest (this also accounts for the large deviations seen near the band edges and in deep valleys of earlier, unfiltered comparisons). Result:
no post filter (beta 0) gives 2.04 dB rms; the best cell is **gamma 0.6, beta 0.275 at 0.74 dB rms**; the PDF's pair
(gamma 0.5, beta 0.2) gives 0.99 dB; leaving the bass boost out at the best cell gives 1.59 dB. The valley is a shallow
ridge: the best `beta` for each `gamma` is 0.20 (0.3), 0.25 (0.4), 0.25 (0.5), 0.30 (0.6), 0.35 (0.7), 0.35 (0.8), with rms
0.83, 0.91, 0.84, 0.82, 0.88, 0.99. So `beta` is 0.2-0.35 and `gamma` 0.3-0.7, and the measurement cannot choose between them.

**Recommended set, from x09's refined pass (0.025 steps)**, quoted from its output lines:

```
RECOMMENDED (refined best): gamma 0.600 beta 0.275 rms 0.737 dB  offset at e=20 27.63 dB  E_MIN_DB+synthesis gain -3.62 dB
PDF PAIR: gamma 0.500 beta 0.200 rms 0.986 dB  offset at e=20 27.16 dB  E_MIN_DB+synthesis gain -4.09 dB
```

Use **gamma 0.6, beta 0.275 with the level offset -3.62 dB** (6.3) as one set; the alternative, with its own offset, is the
PDF's gamma 0.5, beta 0.2 with -4.09 dB. The two are 0.25 dB rms apart. The exponents and the offset must be taken
together. OQ-3 is narrowed to the exact `beta` and `gamma` (a source read of the file holding the two constants would
settle it).

### 6.3 Level

**Dequantizer** `[src: quantise.c @ 310777b]`: the energy in dB is `E_MIN_DB + e * (E_MAX_DB - E_MIN_DB) / 2^5`, with no
half-step offset, so the top level (e = 31) is one step below `E_MAX_DB`; the power is `10^(dB/10)` and scales the
(post-filtered) LPC power spectrum as in 6.2 step 3. The values of `E_MIN_DB`, `E_MAX_DB` were not in the files read.
From the measured 1.5625 dB per step, `E_MAX_DB - E_MIN_DB` = 32 * 1.5625 = **50 dB** (x03; the least-squares slope 1.5656
gives 50.1, so 50 within 0.2 dB).

**Offset** `[exp: tools/blackbox/x09_post_filter_fit.py]`: with the chain of 6.2 and unit energy power, the measured harmonic
power (dB, 20 log10 of the sinusoid peak amplitude) at e = 20 is higher than the chain's band-sum power by the "offset at
e=20" printed for the chosen pair: **27.63 dB for gamma 0.6, beta 0.275** (so `E_MIN_DB` plus the synthesis gain, both in dB, is
27.63 - 20 * 1.5625 = **-3.62 dB**), or 27.16 dB for the PDF pair (-4.09 dB). The synthesis gain (the IDFT scaling) cannot be
separated from `E_MIN_DB` by output alone, so only the sum is given; an implementation can pick any split. The
per-harmonic level then follows from the chain with 0.74 dB rms residual (0.99 dB for the PDF pair) (x09), counting
harmonics within 40 dB of the frame's strongest.

The level applies to each sub-frame's own (interpolated, for sub-frame a) energy and LSPs. The PDF's `E = G^2` reading
(the LPC gain squared) fits: the energy sets an overall scale and the shape comes from `1/|A|` with `a_0 = 1`.

### 6.4 Which harmonics exist

- `L = floor(pi / w0)` `[pdf §3.2]`. Harmonics are exactly at `m * f0` (x02).
- **Harmonic 1 is multiplied by 0.032 in amplitude (about -30 dB) when `w0 < pi * 150 / 4000` rad**
  (0.1178 rad, a 150 Hz fundamental), applied to each sub-frame right after the envelope step, so for sub-frame a with
  its interpolated `w0` `[src: quantise.c, codec2.c @ 310777b]`. The experiment saw harmonic 1 28 to 64 dB down for
  decoded `i` <= 36 (f0 <= 148.4 Hz) and at full level for `i` >= 37 (f0 >= 151.2 Hz), harmonics 2 and up unaffected
  `[exp: tools/blackbox/x06_first_harmonic.py]`; the -30 dB readings (e = 22) are the factor, the deeper ones are
  low-level measurement floor. The threshold 150 Hz is exact, so 150 Hz itself
  (`w0` = 0.1178097) is not scaled; the grid index 37 is 151.2 Hz.
- Harmonics predicted more than 40 dB below the strongest in their sub-frame are not reproduced by a steady-tone
  measurement (they decode with random phase, section 7), so a comparison with `c2dec` should leave them out.

## 7. Phase model (voiced and unvoiced)

State: **open**; described from the PDF `[pdf §3.6]`, which says only what follows. Behaviours that were measured
are marked.

1. Each harmonic's phase is the sum of an **excitation phase** `phi_m` and the phase of the synthesis filter at that
   harmonic: `theta_m = phi_m + arg H(e^{j m w0})`.
2. **Voiced**: the excitation is a pulse train. The first harmonic's excitation phase advances by `N * w0` per
   sub-frame (`N` = 80 samples): `phi_1[l] = phi_1[l-1] + N*w0`, and `phi_m = m * phi_1` for `m` = 2..L. Measured
   consistent with this: in a steady voiced decode the harmonics sit exactly at `m * f0` (x02), which is what a phase
   that advances by `m * w0 * N` per sub-frame gives.
3. **Unvoiced**: the excitation phase of each harmonic is drawn uniformly from (-pi, pi) every sub-frame, and the PDF
   says to use `F0 = 50 Hz` (`L` = 80) so as to approximate noise. The decoder is **deterministic** (the same input
   always gives the same samples, x08 part B), so its noise generator has a fixed seed. For an unvoiced sub-frame
   the output was **not** independent of the transmitted `w0` (x08 part B: w0 index 5 and 100 gave different
   samples), so how `w0` and `L` are used for unvoiced frames is OQ-1/OQ-5.
4. The filter phase `arg H` is the **minimum-phase** response matching the magnitude response of `1/A` sampled at the
   harmonic centres, bin `round(m * r)` `[pdf §3.6, eq. 36]`; the standard way is the cepstrum (or the Hilbert relation
   between log magnitude and phase) (textbook material, unverified). Which
   construction and which sizes: OQ-5.
5. A noise-floor rule: the decoder tracks the background level seen during unvoiced frames, and a harmonic under
   that level gets random phase, i.e. is treated as unvoiced `[pdf §3.6]`. Constants: OQ-5.
6. No attempt is made to keep the final phase (after the filter) continuous across sub-frames; only the excitation
   phase is continuous `[pdf §3.6, note 5]`.

Because randomness only perturbs phases, **bit-exact random numbers are not needed** for a log-spectral-distance
comparison with `c2dec`; any uniform generator seeded per decoder instance is acceptable, so long as it is deterministic
`[c2fx design]`.

## 8. Synthesis

`[pdf §3.3]`, with the timing confirmed by the amplitude ramps measured in x07:

1. For each sub-frame fill a spectrum array of `N_dft` bins with zeros; for each harmonic `m` = 1..L put the complex
   value `A_m * exp(j*theta_m)` at bin `round(m * r)` (`r` as in 6.1), and its conjugate at the mirrored bin so the
   result is real `[pdf eq. 10-11]`.
2. Inverse DFT: real output, `N_dft` = `FFT_DEC` = **512** `[src: defines.h @ 310777b]` (> 2N = 160 `[pdf §3.3]`).
   The hop is `N_S` = 10 ms = **80 samples** and there are at most `MAX_AMP` = **160** harmonics `[src: defines.h]`;
   `P_MIN_S` 2.5 ms and `P_MAX_S` 20 ms give the pitch limits (period 20..160 samples).
3. Window the 160-point result with a **triangular** window `t(n) = n/80` for `n` = 0..79 and `2 - n/80` for `n` =
   80..159 `[pdf eq. 13]`; adjacent windows 80 samples apart sum to 1 `[pdf eq. 14]`. The PDF says the shape does not
   matter as long as that sum holds. The source has a synthesis-window overlap constant `TW_S` = 5 ms = **40 samples**
   (a trapezoidal window with 40-sample ramps), and the window buffer is allocated for 2 x 80 = 160 samples; the shape and
   length actually used come from a routine in a file that was not read `[src: defines.h, codec2.c @ 310777b]`. The
   black-box ramps do not look trapezoidal: the amplitude of a steady harmonic moves steadily over 160 samples with a
   change of slope at the sub-frame centre `[exp: tools/blackbox/x07_interpolation.py part C]`, which is what two
   80-sample triangles give. The coded window (OQ-6) stays open; use the triangle, which reproduces the measured ramps.
4. Which 160 samples: the block is **centred on index 0 of the IDFT output, wrapping circularly**: its first 80 samples
   (the rising half of the window) come from the last 80 samples of the IDFT output and its last 80 (the falling half)
   from the first 80 `[pdf §3.3, eq. 15]`. The printed index offsets in that equation differ by one sample from this
   reading; that one-sample question is part of OQ-6.
5. Overlap-add: output samples `0..79` of the sub-frame are the first half of the windowed block plus the stored second
   half of the previous sub-frame's block; the second half is stored for the next sub-frame `[pdf §3.3, eq. 15]`.
6. Rounding to int16 with saturation at +-32767 (observed clipping, x08).

**FFT size.** Both transforms the decoder needs are 512 points: the real FFT of the LPC coefficients (`FFT_ENC`) and
the inverse real FFT of the synthesis (`FFT_DEC`) `[src: defines.h, codec2.c @ 310777b]`. One 512-point real FFT and its
inverse therefore serve the envelope and the synthesis; the transform for the minimum-phase filter phase (section 7, OQ-5)
is not known.

## 9. Lost frames `[c2fx design]`

Upstream's decoder has no lost-frame handling (it always decodes the frame it is given). This section is **our own
design**: the library's decode call takes a null frame pointer to mean "frame lost".

- Repeat the previous frame's model (w0, LSPs, voicing as decoded for sub-frame b) for the lost frame, with the
  energy index lowered by a fixed number of steps per consecutive lost frame (starting proposal: 2 steps = 3.125 dB),
  for a fixed maximum run (starting proposal: 4 frames = 80 ms). After the run, output silence and keep the state so a
  good frame next fades in through the normal start-up path.
- Sub-frame a of the lost frame is the interpolation of the previous b with the repeated (decayed) b, as for any frame.
- The run length and the decay are parameters to be fixed with the float model; the requirement is that output stays
  bounded and mutes after the repeat limit. The constants above are starting points, not facts about upstream.

Deciding that a frame is bad stays with the caller (the M17 layer).

## What the PDF gives, and which files hold the tables

**What `codec2.pdf` gives for 3200.** The bit allocation (7 pitch, 5 energy, 2 voicing, 50 for the spectral amplitudes);
that LSP **differences** are quantised, at some cost in robustness to bit errors; 20 ms frames with a 10 ms internal
rate and linear interpolation between; the pitch range (50-400 Hz) and `L = floor(pi/w0)`; the structure of the post
filter with `beta = 0.2`, `gamma = 0.5` and a +3 dB low-frequency boost; the zero-order phase model; and the IDFT
overlap-add synthesis with a triangular window and hop 80. It does **not** give the field order, the Gray coding, the
`w0` and energy ranges and steps, the tables, the interpolation weights, the voicing rule, or any constant of the phase
model and the level normalisation; those come from experiment here.

**Which codebook files.** `dlsp1.txt` through `dlsp10.txt` in upstream's `src/codebook/` (one file per LSP difference),
each a header line `1 32` and 32 values in Hz: 10 files, 320 numbers. The other LSP files (`lsp1..10.txt`,
`lsp8910.txt`, `lspjmv*`, `lspvqexp*`) belong to other modes, and `gecb.txt`, `newamp*`, `codes_450.txt` and `train_*`
are not 3200. `w0` and the energy have no table: they are formulas (3.2, 3.3). All ten files follow the two regular
patterns of 3.4.

**Model dumps.** `c2sim ... --modelout <file>` writes a per-10 ms model dump without any source change (record layout in
`tools/blackbox/README.md`); with `--rate 3200` the dumped `w0` is already on the 3200 grid. The record's fields were
inferred from size and values only.
